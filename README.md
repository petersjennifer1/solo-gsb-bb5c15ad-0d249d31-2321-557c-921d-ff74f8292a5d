# 字幕校订台（Subtitle Revision Studio）

供纪录片剪辑使用的**本地**字幕校订网页工具：上传带时码的旧版 SRT 与逐行修订台词，自动做全局顺序对齐（支持一条拆两条、两条并一条），人工复核配对与时码后预览并下载成品 SRT。数据不出本机。

## 快速启动（单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**

> 依赖安装与初始化全部在镜像构建/启动阶段完成，无需任何额外步骤。
>
> 切点等功能均在校订页（第 2 步）使用；页面与接口只在本机端口提供（Docker Compose 默认映射 `8080:8080`）。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 服务监听端口。改端口请同步修改 `docker-compose.yml` 的 `ports` 映射，如 `"9000:9000"` 并设 `PORT: 9000` |

不使用 Docker 的本地开发方式：

```bash
npm install
npm start          # 访问 http://localhost:8080
npm test           # 运行对齐引擎测试（node:test，无需额外依赖）
```

## 使用流程

1. **上传素材**
   - 旧版字幕：`.srt` 文件（带时码），或直接粘贴内容；
   - 修订台词：`.txt` 文件，**每行一句**（行首的 `1.`、`1、` 等序号会自动剥除），或直接粘贴。
2. **自动对齐**：点击「开始对齐」。算法对两份文本做单调全局最优对齐：
   - **一拆二**：按修订文字长度比例分配原时段（单条最短 400ms 保护）；
   - **二并一**：沿用两条旧字幕的覆盖时段（首条开始 ~ 末条结束）；
   - **重复台词**：对齐是全局有序的，相同台词会结合前后内容自动归位到正确的那一处；
   - 修订稿中新增的行插值临时时段并标记「未匹配」；旧字幕中被删除的条目列入「被丢弃的旧字幕」。
3. **校订**：带「不确定 / 未匹配 / 倒序 / 重叠」标记的行为待处理行（可勾选「仅看待处理行」）。每行支持：
   - 直接修改台词文本与时码（格式 `HH:MM:SS,mmm`）；
   - **锁定**：勾选某行的锁定开关后，该行时码在匀时时保持不变（锁定时手改时码输入框置灰）；
   - **区间匀时**：点击「区间匀时」，按下方规则批量重排未锁定行时码；
   - **避切点**：在「镜头切点」框中**每行输入一个切点**（格式 `HH:MM:SS,mmm`，见下方说明），点击「避切点」，对跨越切点的未锁定行自动改时码（规则见下方）；
   - **拆分**：指定字符位置把一行拆成两条，按长度分配时段；
   - **合并**：与下一行并成一条，沿用覆盖时段；
   - **确认**：人工复核后清除该行的待处理标记；**删除**：移除该行。
4. **预览与下载**：点击「确认并预览」生成 SRT 预览（仍有待处理行、或**仍跨越切点的行**时会在预览页提示行号），确认后「下载 SRT」得到 `revised.srt`（UTF-8 带 BOM，兼容常见播放器与剪辑软件）。匀时与避切点结果都沿用校订后的当前时码走该预览与导出流程，并自动复用重叠标记。

### 镜头切点格式

- 在「镜头切点」输入框中**每行写一个**切点，格式为 **`HH:MM:SS,mmm`**：
  - 24 时制，小时 2 位（超过 1 小时可写 3 位），分、秒均为 `00`–`59` 两位，毫秒 3 位，**使用英文逗号**；
  - 例：`00:01:02,500`、`00:00:00,000`、`01:23:45,120`；空行会被忽略。
- 点击「避切点」时若存在格式错误的行，会指出**输入框中的行号**与内容，**不改动任何字幕**；修正后再点即可。
- 切点恰在某行开始或结束位置时不算跨越，该行不会被调整。

### 避切点规则

- 只处理**跨越切点的未锁定行**（`开始 < 切点 < 结束`）；锁定行时码不变——若锁定行本身跨越切点，会在结果中提示行号；
- 每行优先在两种缩短方式中选择：**在切点前结束**（保留原开始）或**从切点后开始**（保留原结束）；若缩短后不足 400ms，则允许**整行平移**到切点前/后（必要时补足最小时长）；
- 相邻受影响行的选择会互相牵制（相邻行至少间隔 100ms），对连续受影响行做**联合选择，取总时码改动量（各行开始/结束偏移绝对值之和）最小**的方案；
- 始终保证：**每行至少 400ms、相邻行之间至少 100ms、锁定行时码不变，且调整后不再跨越切点**；
- **没有可行方案的行保留原时码**，结果区逐行显示**行号与原因**（如两侧放不下 400ms、被相邻锁定行牵制、相邻行联合无解等），表格中相应行红色高亮并带「跨切点」徽标；
- 成功调整后仍跨越切点的行（锁定行 / 无可行方案行）会在结果区与预览页提示行号；修改时码或重新点击「避切点」可再次尝试。

### 区间匀时规则

- 按**连续未锁定行**分段：每段以**前一锁定行的结束**与**后一锁定行的开始**为边界（含 100ms 行间隔）；段首/段尾没有锁定邻居时，**沿用该段原首行开始、原末行结束**；
- 仅重排段内未锁定行，按各台词**去除字幕标记（`<i>` 等标签、`{\an8}` 类覆盖标签）后的可见字符数**加权分配时长，保持原顺序，**单行至少 400ms、相邻行之间至少 100ms**，且不得越过锁定行；
- 某区间容量不足以容纳最小时长时，**整段保留原时码**并在匀时按钮下方提示行号范围及所需/可用时长（对应行红色高亮）；其他可行区间照常更新。调整锁定或时码后可再次匀时。

## 项目结构

```
server.js            Express 服务：静态页面 + /api/align + /api/evenize + /api/avoidcuts + /api/export
src/srt.js           SRT 解析/序列化与时码工具
src/align.js         对齐引擎（带状全局 DP：配对/拆分/合并/跳过 + 标记）
src/evenize.js       区间匀时引擎（锁定行切段、按可见字数分配、最短时长/间隔保护）
src/avoidcuts.js     避切点引擎（切点前结束/切点后开始/整行平移候选 + 相邻行联合最小改动 DP）
public/              原生前端（无构建步骤）
test/                引擎与接口测试（node --test）
Dockerfile           单阶段镜像，启动即完成依赖安装与初始化
docker-compose.yml   单服务编排，默认映射 8080:8080
```

## 对齐规则说明

- 文本比较前会归一化：去标点/空白、全角转半角、小写化、剥除 `<i>` 等标签与 `{\an8}` 类覆盖标签；
- 相似度为字符 unigram/bigram 的 Dice 均值，低于 0.45 的配对标记「不确定」；
- 导出前服务端会再次校验：时码倒序或文本为空会被拒绝，重叠行会在预览中提示。
